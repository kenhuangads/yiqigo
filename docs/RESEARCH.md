# 競品研究與產品決策（2026-08）

本文件整理海內外主流翻譯工具的實測觀察與公開資訊，並說明「一起GO 翻譯神器」每項功能的設計依據。市場總體分析詳見《[產品發展計畫](product-plan.md)》。

## 一、競品矩陣

| 工具 | 強項 | 對台灣用戶的缺口 | 我們的回應 |
| --- | --- | --- | --- |
| **Google 翻譯** | 133+ 語言、AR 即時鏡頭翻譯、離線語言包 | 繁中結果常帶簡體語彙痕跡（充電寶、視頻）；口語生硬 | 台灣用語守護管線（OpenCC s2twp＋自建詞典）強制在地化 |

| **Payke** | 掃商品條碼看繁中成分（2026-04 新增 AI 購物顧問） | 僅限資料庫內商品，非通用翻譯 | 照片翻譯可拍任何成分表；過敏原高亮列入藍圖 |

## 二、核心洞察 → 產品決策

### 1. 台灣旅客的「多 App 疲勞」
研究顯示台灣旅客出國要同時裝 Google（看路標）、Papago（日韓對話）、Payke（藥妝）、DeepL（文件）。
→ **決策**：單一 App 聚合五大場景（對話／相機／輸入／照片／句庫），底部一列 tab 全部到位。

### 2. 繁中翻譯的「簡體殘留」是最大痛點
「一簡對多繁」（发→發/髮、面→面/麵）與大陸用語（充電寶、打車、酸奶）讓台灣用戶產生剝奪感。
→ **決策**：所有中文輸出強制經過 OpenCC `s2twp` ＋ 60 條自建台灣詞典，介面顯示「台灣用語守護 ✓」讓價值可感知。

### 3. 對話延遲與「機器人腔」
傳統 STT→MT→TTS 串聯延遲 1–3 秒且語氣全失。
→ **決策（MVP）**：瀏覽器原生 STT 串流顯示中間結果（interim results），使用者「邊說邊看到字」，心理延遲大幅下降；翻譯完成即自動 TTS。
→ **決策（藍圖）**：接入 OpenAI Realtime / Gemini Live 端到端語音，目標 <300ms 並保留語氣。

### 4. 日本是台灣人第一目的地（佔 35%+）
日文需求最大宗，且日本菜單／書籍大量使用直式排版，一般 OCR 全滅。
→ **決策**：語言預設值就是日文；OCR 提供「日文（直式）」專屬模式（Tesseract `jpn_vert` + PSM 5）。

### 5. 免費與成本結構
參考文件指出雲端語音 API 單客日成本可能超過 1 美元，動態路由是獲利關鍵。
→ **決策（MVP）**：翻譯走免費雙引擎（Google gtx / MyMemory 容錯切換）＋工作階段快取＋Service Worker 重複查詢快取，營運成本為零；未來高階功能（Realtime 語音、文件解析）走 Freemium 訂閱。

### 6. 離線是旅遊場景的硬需求
飛機上、地下鐵、偏遠景區斷網是常態。
→ **決策（MVP）**：句庫 100% 離線（人工校對四語，不依賴機器翻譯）；PWA 快取 App 殼層與 OCR 模型；重複翻譯過的句子離線可查。
→ **決策（藍圖）**：whisper.cpp / llama.cpp 端側模型，實現全功能離線。

## 三、四語預設的市場依據

| 語言 | 依據（台灣出境結構） |
| --- | --- |
| 繁體中文 | 母語，所有翻譯的目標／來源軸心 |
| 日文 | 第一大目的地（35–37%，年 670 萬人次） |
| 韓文 | 第三大目的地（180 萬人次+，醫美／追星／購物需求強） |
| 英文 | 全球通用語，歐美澳與轉機場景 |

架構上語言表集中在 `js/config.js`，新增泰文／越南文（成長最快目的地）只需增加一筆設定與句庫資料。
